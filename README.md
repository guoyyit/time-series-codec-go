# time-series-codec-go

面向长期高吞吐写入场景的时序数据压缩存储引擎。写入路径（WAL + 内存表）
与查询路径（块索引 + 解码）解耦：写入只需追加日志并更新内存结构，查询直接
定位压缩块解码，无需从头重放。

```
codec/   压缩块编解码（无损 Gorilla 风格 / 有损 epsilon 有界量化）
store/   存储引擎（WAL、内存表、数据文件、索引快照、崩溃恢复、后台合并）
```

## 快速开始

```go
cfg := store.Config{
    Dir:            "/var/lib/tsdb",
    Codec:          codec.Config{Codec: codec.CodecLossless},
    MaxBlockPoints: 4096,          // 每个压缩块的点数（刷盘阈值）
    MinMergeBlocks: 4,             // 后台合并触发阈值
    CompactInterval: time.Minute,  // 后台合并周期，0 表示手动
}
s, err := store.Open(cfg)
...
err = s.Write("cpu.usage", codec.Point{TS: ts, V: v}, ...)
pts, err := s.Query("cpu.usage", start, end)   // 半开区间 [start, end)
err = s.Close()
```

## 压缩语义

### 无损模式（CodecLossless）

- 时间戳：delta-of-delta（二阶差分）位流编码，桶自适应位宽。
- 数值：Gorilla 风格 XOR 位流编码（与前值异或后按前导/尾随零窗口压缩）。
- **解码结果与原始写入逐比特一致**（包括 NaN、±Inf、-0.0）。

### 有损模式（CodecLossy）

- 时间戳**始终无损**（与上相同）。
- 数值按步长 `step = 2*Epsilon` 量化：`q = round(v / step)`，解码值
  `v' = q * step`。数学上保证 **|v' − v| ≤ Epsilon**（绝对误差上界，
  可解释、可验证）。
- 量化后的整数序列做 delta + zigzag-varint 编码。
- 无法安全量化的值（NaN、±Inf、超出 int64 量化范围的极大值）自动进入
  "精确值旁路列表"，按原始比特存储——**有损模式不会静默丢失或扭曲
  特殊值**。

### 块自描述与配置变更

每个块头记录 `codec id` 与 `epsilon`，解码完全由块自身决定：

- 运行中或重启后修改 `Config.Codec` / `Epsilon` **只影响新写入的块**，
  既有块永远可按原语义解码。
- 后台合并重编码历史块时遵循 **never-degrade** 策略：只要源块中存在
  无损块，合并输出仍为无损；全为有损时取最小 epsilon。即配置变更
  （包括改为有损）不会降低既有数据的精度。
- 有损块在固定 epsilon 下重复压缩是幂等的（量化值落在网格上，
  再次量化不产生额外漂移）。

## 写入语义

- **乱序/迟到**：样本先写入按时间戳排序的内存表，刷盘时块内必然有序；
  迟到样本会形成时间范围重叠的新块，由查询归并和后台合并处理，
  不会导致块内乱序或查询漂移。
- **重复**：同一时间戳后写覆盖先写（last write wins）。内存表内即时
  去重；跨块/跨内存表的重叠在查询与合并时按"块序列号新者胜、内存表
  最新"的规则去重。
- **持久性**：每次 `Write` 先追加 WAL 并 fsync，再应用到内存表；
  `Write` 返回即已落盘。崩溃后重放 WAL 恢复未刷盘数据。

## 查询语义

- `Query(series, start, end)` 返回半开区间 `[start, end)` 内按时间戳
  升序、去重后的点。
- 查询只解码与区间重叠的块（经索引裁剪），**不依赖从头重放**。
- 结果与"全量重放所有写入（last write wins）"严格一致，包括块边界
  与乱序样本附近（见 `TestQueryMatchesFullReplay` 随机化验证）。

## 崩溃恢复

- 数据文件只追加；块记录带帧头与 CRC32，撕裂的尾部记录不会被索引引用。
- 索引快照采用"写临时文件 + fsync + rename + fsync 目录"原子替换，
  崩溃只会留下被忽略的 `index.tmp`。
- 快照记录 WAL 回放起点（`WALGen`）：刷盘 = 编码全部内存表 → 追加数据
  文件并 fsync → 持久化新快照 → 轮换 WAL 并清理旧代。任意时刻崩溃：
  快照未更新则旧 WAL 重放恢复；快照已更新则块已持久化。WAL 尾部的
  撕裂记录（CRC 不符/长度不足）在回放时截断。
- 主索引损坏会**报错拒绝启动**（而不是静默丢数据）；孤儿数据文件在
  下次启动或合并时回收。

## 后台合并

- 触发：系列内块数 ≥ `MinMergeBlocks`；由 `CompactInterval` 周期驱动
  或手动 `CompactOnce()`。
- 过程：解码源块 → 按 last-write-wins 去重 → 按 `MaxBlockPoints` 重新
  分块 → 以 never-degrade 策略重编码 → 写入新数据文件 → 原子替换索引
  → 删除完全失去引用的旧文件。
- 合并全程持有写锁做索引交换，**并发读写不会看到中间状态**；崩溃时
  旧快照与旧块仍在盘上，不会丢失已提交数据。

## 容量估算

实测（4096 点/块，1s 等间隔采样，缓变正弦值，见
`TestCompressionRatioSanity`）：

| 模式 | 字节/点 | 相对原始（16 B/点） |
|------|---------|---------------------|
| 无损 | ~7 B    | ~44%                |
| 有损 (ε=0.01) | ~1.1 B | ~7%            |

估算公式：

```
日存储量 ≈ 序列数 × 每序列日点数 × 字节/点 × (1 + 开销系数)
```

- 块头固定 36 B/块（含 CRC），块越小开销越大：4096 点/块时 < 0.3%。
- WAL 为未刷盘数据的临时副本（刷盘后回收），稳态可忽略；崩溃恢复
  期间最大约等于一个刷盘周期的写入量。
- 索引约 40 B/块 + 系列名，十万块级仅数 MB。
- 合并期间新旧文件短暂并存，预留约 1 倍单系列数据量的峰值空间。

数值越"平滑"（相邻值 XOR 后前导零越多）无损压缩率越高；有损模式的
字节/点随 epsilon 增大而下降（量化后 delta 更小）。
